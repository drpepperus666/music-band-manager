                               4.1. Коллекции данных
    Коллекции – это структуры данных, предназначенные для хранения наборов зна-
чений. До настоящего момента программа индивидуального проекта работала с от-
дельными переменными; коллекции позволяют перейти к обработке наборов данных:
перечню помещений, списку бронирований, словарю товаров. В Python используются
четыре основные коллекции:
• список (list) – упорядоченная изменяемая коллекция; используется, когда важен
  порядок элементов и их состав может меняться;
• кортеж (tuple) – упорядоченная неизменяемая коллекция; подходит для фиксиро-
  ванных наборов значений;
• множество (set) – неупорядоченная коллекция уникальных элементов; применя-
  ется для проверки принадлежности и устранения повторов;
• словарь (dict) – коллекция пар «ключ – значение»; используется, когда элементы
  нужно находить по смысловому идентификатору.
                                            5
    Для выбора коллекции достаточно ответить на два вопроса: важен ли порядок
элементов и как элементы будут искаться. Так, содержимое холодильника удобно
представить словарем, ключом которого является название продукта, а значением –
количество и срок годности; перечень бронирований – списком словарей.
                            4.2. Итерации и циклы
    Циклы обеспечивают многократное выполнение действий и применяются сов-
местно с коллекциями: перебор элементов, накопление результата, поиск и фильтра-
ция данных. Совместное использование коллекций и циклов – основной прием обра-
ботки данных в программах на Python.
• цикл for перебирает элементы коллекции; количество повторений определяется
  самой коллекцией;
• цикл while повторяет действия, пока выполняется условие; применяется, когда ко-
  личество повторений заранее неизвестно;
• функция range() используется для перебора целых чисел и формирования после-
  довательностей;
• с помощью циклов обрабатываются словари: ключи, значения и пары «ключ – зна-
  чение».
     В проекте «Холодильник» циклы применяются при переборе продуктов и фор-
мировании отчета о содержимом, а в индивидуальном проекте – при обработке спис-
ков помещений и бронирований и при организации основного цикла меню.
                                 4.3. Функции
    Функция – это именованный блок кода, выполняющий конкретную операцию.
Выделение функций уменьшает дублирование, упрощает отладку и позволяет соби-
рать программу из логически завершенных частей. На ПР1 в начальном сценарии
была реализована одна функция; на ПР2 функциональность программы сознательно
распределяется между несколькими функциями.
• параметры задают исходные данные функции;
• инструкция return возвращает результат; функция без return возвращает None;
• одна функция должна выполнять одну логически завершенную операцию;
• документирующая строка (docstring) кратко описывает назначение функции, её
  параметры и результат.
    При проектировании функций индивидуального проекта следует опираться на
состав операций предметной области: проверка возможности бронирования, создание
брони, поиск и фильтрация данных – каждый из этих сценариев становится отдельной
функцией.

                             4.4. Модули и пакеты
     Модуль – это файл с расширением .py, содержащий определения функций и дру-
гие объекты языка. Пакет объединяет несколько модулей в общую структуру катало-
гов. Организация кода в виде модулей делает программу обозримой: каждый файл
отвечает за свою часть функциональности, а подключение выполняется инструкцией
import.
• стандартные модули Python подключаются инструкцией import и расширяют воз-
  можности программы;
• собственный модуль создается как обычный .py-файл и подключается по имени;
• функция main() служит точкой входа и организует взаимодействие с пользовате-
  лем;
• разбиение на модули выполняется по смыслу: логика предметной области, работа
  с данными, вспомогательные функции.
     Навык организации модулей напрямую используется в индивидуальном проекте:
на ПР2 программа разделяется на несколько файлов, что готовит проект к дальней-
шему усложнению.
                                4.5. Исключения
     Исключение – это ошибка, возникающая во время выполнения программы: не-
корректный ввод пользователя, отсутствие файла, недопустимое значение. Механизм
обработки исключений позволяет перехватить ошибку и завершить сценарий пред-
сказуемо, не прерывая работу программы аварийно.
• конструкция try содержит код, в котором может возникнуть ошибка;
• блок except перехватывает и обрабатывает конкретный тип исключения;
• инструкции else и finally дополняют обработку: первая выполняется при отсут-
  ствии ошибок, вторая – в любом случае;
• типичные исключения: ValueError, TypeError, KeyError, FileNotFoundEr-
  ror.
     В индивидуальном проекте исключения обрабатывают некорректный ввод поль-
зователя и ошибки при работе с файлами данных – это обязательное требование к
программной части ПР2.
               4.6. Работа с файлами и контекстные менеджеры
     Файлы позволяют сохранять данные между запусками программы. В учебном
проекте удобно использовать формат JSON: он поддерживается стандартным моду-
лем json и хорошо подходит для хранения списков и словарей. Чтение и запись файла
выполняются через контекстный менеджер with, который автоматически закрывает

                       6.3.7. Первичное тестирование проекта
     Настройте первичное автоматизированное тестирование проекта с использова-
нием pytest. Автоматизированные тесты проверяют работу функций без ручного
запуска программы и подтверждают корректность реализации после доработки про-
екта.
       Порядок настройки:
• установите pytest в рабочее окружение: pip install pytest (или установите
  зависимости проекта из файла requirements.txt);
• создайте в проекте каталог tests (предусмотрен структурой проекта);
• создайте не менее одного файла тестов, например tests/test_rooms.py;
• реализуйте 3-5 простых автоматизированных тестов;
• запустите тесты из корня проекта командой pytest.
    В первую очередь тестируйте функции, которые не требуют сложной настройки
окружения: функции обработки данных, принимающие коллекции и возвращающие
результат. Каждый тест проверяет одну функцию на одном сценарии и завершается
проверкой assert.
