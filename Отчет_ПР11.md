## 4. Формы проекта

- `RehearsalFilterForm` (`rehearsals/forms.py`, `forms.Form`):
  `date` (`DateField`, `DateInput type=date`), `band`
  (`ModelChoiceField`, `empty_label`), `q` (поиск),
  `sort` (`ChoiceField`: date/band/participants); всё
  `required=False`. Связь — `RehearsalFilterForm(request.GET or None)`,
  значения — только из `cleaned_data` после `is_valid()`.
- `RehearsalForm` (`forms.ModelForm`, `fields = ["band",
  "rehearsal_date", "participants"]`, `labels`/`help_texts`,
  виджеты Bootstrap; `participants` — `IntegerField(1–100)`):
  `clean_rehearsal_date()` запрещает прошлое
  (`timezone.localdate()`); `clean()` запрещает дубль активной
  репетиции (`active().filter(...).exists()`, при редактировании —
  `exclude(pk=self.instance.pk)`); статус задаёт сервер.
- `BandImageForm` (`bands/forms.py`, `fields = ["image"]`) —
  загрузка фото группы.

## 5. Представления и маршруты

- `rehearsal_list`: форма вместо ручного `request.GET`; сохранены
  `active()`, фильтры, `annotate(F)` + `values`, белый список
  сортировки, `Paginator` по 5, `{% querystring %}`. Ошибка —
  «Проверьте корректность параметров фильтрации» + ошибки полей.
- `rehearsal_create` (`create/`): GET — пустая форма
  (`initial` = сегодня); POST — проверка → `save()` → `redirect`
  к списку; занятость/прошлое — повторный показ с ошибками.
- `rehearsal_update` (`<id>/edit/`, только active, `instance=`):
  те же проверки, запись не конфликтует сама с собой;
  несуществующий id — 404.
- `rehearsal_cancel` (`<id>/cancel/`, `@require_POST`): только
  active → `cancel()` (статус, без удаления); повтор — 404,
  GET — 405.
- Фото: `band_detail` принимает `request.FILES`
  (`enctype="multipart/form-data"`), `MEDIA_URL`/`MEDIA_ROOT` +
  `static()` при `DEBUG` (`media/` в `.gitignore`); показ через
  `{{ band.image.url }}`; поле доступно и в админке.

## 6. Валидация и безопасность

Серверная проверка везде: типы/обязательность/`ChoiceField`/
`ModelChoiceField` (несуществующая группа отклоняется), прошлое,
занятость (`exists()`), `ValidationError` → `field.errors` /
`non_field_errors`. Изменяющие операции — только POST
с `{% csrf_token %}`; `status` и `slug` недоступны формам.
