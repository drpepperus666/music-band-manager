## 4. Фильтрация с использованием GET-параметров

Представление `rehearsal_list` связывает форму с запросом:
`form = RehearsalFilterForm(request.GET or None)`, далее
`form_valid = form.is_bound and form.is_valid()`. Значения берутся
только из `cleaned_data` после успешной проверки; `page` — не поле
формы, читается из `request.GET` отдельно. Невалидный ввод — сообщение
«Проверьте корректность параметров фильтрации» + ошибки полей,
фильтрация не применяется; пустая форма — полный список активных.
Пагинация сохраняет фильтры через `{% querystring %}`.

## 5. Валидация данных и обработка ошибок форм

Серверная проверка: типы и `required` (Django), `ModelChoiceField`
(несуществующая группа отклоняется), `ChoiceField` (чужой `sort`
отклоняется), `clean_rehearsal_date()` (прошлое запрещено,
`timezone.localdate()`), `clean()` (дубль активной репетиции —
`active().filter(...).exists()`, при редактировании —
`exclude(pk=self.instance.pk)`), `ValidationError` → `field.errors`
и `form.non_field_errors`. Шаблоны: цикл полей (`label_tag`, поле,
`help_text`, ошибки) + общие ошибки; в списке — ошибки под каждым
полем. Значения сохраняются при повторном показе формы.

## 6. Создание и редактирование через ModelForm

`rehearsal_create` (`rehearsals/create/`): GET — пустая форма
(`initial` = сегодня); POST — `RehearsalForm(request.POST)`,
`is_valid()` → `save()` → `redirect("rehearsals:list")`.
`rehearsal_update` (`<id>/edit/`, только active): `instance=`,
общий шаблон `rehearsal_form.html` (заголовок/кнопка по
`{% if rehearsal %}`). Статус в форму не входит
(`default=active` модели). Без `instance` создаётся новая запись —
дубликатов при редактировании нет (проверено).

## 7. Проверка даты и доступности помещения

Прошлое запрещено в `clean_rehearsal_date()`; занятость — в `clean()`
через `Rehearsal.objects.active()` + `exists()` (отменённые
и завершённые не блокируют). В `available_bands` и карточке группы —
тот же `active()` (`for_date(...)`, `exists()` на сегодня).
Проверено: дубль активной — ошибка без сохранения; дата только
с отменённой — создание разрешено; редактирование себя — без
ложного конфликта; конфликт с чужой активной — ошибка.

## 8. Отмена бронирования и изменение статуса

`rehearsal_cancel` (`<id>/cancel/`, `@require_POST`): поиск только
среди `active()` → `rehearsal.cancel()` (статус `cancelled`,
`save(update_fields=["status"])`, запись сохраняется). Повторная
отмена — 404, GET — 405. Кнопка «Отменить» — POST-форма с CSRF
в строке списка. После отмены запись скрыта из списка активных
и не блокирует дату (проверено на одной дате).

## 9. Результаты проверки пользовательских сценариев

| Сценарий | Результат |
| --- | --- |
| Фильтр (дата/группа/поиск/сорт) + пагинация | 200, выборка и порядок верные, параметры сохраняются |
| Создание корректное | 302, запись active в списке |
| Прошлая дата | 200 + ошибка, не сохранено |
| Дубль активной | 200 + ошибка занятости, дубликата нет |
| Редактирование (себя/конфликт/404) | 302 / ошибка / 404, дубликатов нет |
| Отмена (POST/повтор/GET) | 302 + cancelled / 404 / 405 |
| Фото (загрузка/показ/удаление) | Файл в `media/bands/`, показ `image.url`, очистка работает |
| Данные после прогонов | 2 группы / 1 участник / 1 репетиция, дерево чистое |
